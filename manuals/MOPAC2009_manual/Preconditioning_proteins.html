Preconditioning Proteins

Introduction

The MOZYME function provides a very powerful tool for the study of proteins, in particular globular proteins.  Only systems that can be described with a closed shell wavefunction can be modeled.  In addition to proteins composed only from the standard 20 residues, more complicated proteins, such as bacteriorhodopsin, myoglobin, cytochrome-P450, and hemoglobin can also be modeled.  Organometallic enzymes, particularly those involving the heme system, are normally regarded as open shell, but their structures can apparently be represented with good accuracy using the PM6 RHF method.  No problems should occur with even quite large systems: structures of systems of almost 10,000 atoms have been optimized in a few CPU weeks.  However, problems are likely to occur in systems with significantly more than 10,000 atoms.

The most difficult operation in calculating protein structures involves preparing the data set.  None of the common sources of reference data for protein geometries are suitable for use as a data set.  This includes, in particular, the Protein Data Bank (the PDB). While all the proteins used in developing the MOZYME function were obtained from the PDB, in every case extensive work had to be done in preparing a data set that could be run using MOZYME.  Common deficiencies or features that make the raw PDB files unsuitable are:

  • For most PDB entries, hydrogen atoms are missing. 

  • There might be positional disorder (groups of atoms can occupy two possible conformations, and the PDB file records both)

  • There might be structural disorder (different residues in the same position in the sequence, e.g. ILE and LEU might both be present a fraction of the time in a given position.)

  • Residues might be missing.  (These are usually only those residues on the surface of a protein that are not involved in activity, and are not tightly bound.)

  • Exotic atoms might be present, e.g. Hg, Sm, or La.

All these features and faults must be addressed before a MOZYME run can be started.

Recommended Sequence for Preconditioning a Protein Data Set

1. Before starting, get a copy of the data set representing the protein of interest; the PDB is an excellent source for such data files.

2. The first operation is to resolve positional and structural disorder.  Most GUIs that can handle PDB files will be able to do this when the data set is read in.  Look at the data set.  If there are gaps in the residue sequence, find out whether these represent genuine gaps or represent missing data.  Normally, gaps are not very important, and can safely be ignored. The rare case is when there are one or more residues missing inside the protein - this normally would require the missing residues to be replaced.

3. If necessary, add hydrogen atoms.  Even if the protein already has hydrogen atoms, quite often several of them are missing.  During this operation, several problems can occur. The commonest complications are:

  • Too many or too few hydrogen atoms are added to a heavy atom resulting in an ionized site.  Ensure that all atoms are formally neutral, this includes all the carboxylate and primary amine groups.  All carboxylate groups should be neutral, e.g. -COOH, not -COO(-), as should all primary amines, e.g. -NH2, not -NH3(+) . 

  • Too many or too few hydrogen atoms are added to a heavy atom resulting in the wrong saturation.  Thus if a phenyl group has excess hydrogen atoms, it might be converted to a cyclohexane.

  • Check hetero groups carefully.  Thus heme should have the correct porphyrin ring structure, and small hetero groups, such as carbon monoxide and molecular oxygen, should not have "extra" hydrogen atoms.

4. Prepare a MOPAC data set; use Cartesian coordinates.  In the first run, use keywords 0SCF and RESEQUENCE.  This will re-arrange the atoms into the standard PDB sequence.  All hydrogen atoms that were added will be moved to be with the heavy atoms of the residue. Using a GUI, look at the resulting structure.  There should be no unknown residues.  If there are, and you're sure that they are correct, use keyword XENO to allow the unknown residue to be related to one of the 20 standard residues. This step is not essential, but if it's done then potential problems associated with the unusual residue can be more rapidly located., if it's not done, the unknown residue will be indicated as UNK

5. Use the output to prepare a new data set.  Run this set using keywords CHARGES. If a message of the type:

For atom 2401 number of bonds: 6: 1451 2402 2441 2442 2443 2478

is printed, the data set will need to be modified to remove one or more bonds.  In this example, atom 2401, an iron atom in a heme ring, forms four bonds to the nitrogen atoms of the porphyrin ring, and two bonds to ligands above and below the ring.  If these two bonds are removed, the job should be able to continue.  The bonds can be removed with the keyword:

CVB(2401:-1451,2401:-2478)

Once the extra bonds are removed, a list of all charged sites found will be printed at the end of the output.  Ideally, this list should be empty, but in practice most data sets at this point contain charged sites.  Using the GUI, carefully look at the various sites, and work out what needs to be changed.  Be aware that MOZYME will break bonds as necessary to ensure that each atom only bonds to a maximum of four other atoms.  This can result in apparent charges, thus H2SO4 would involve S2+, two hydroxyl groups, and two O- ions. Likewise, SF6 would be represented as [SF4]2+ + 2F-.  Make any corrections necessary. If corrections are made, consider re-running RESEQUENCE.

6. Prepare a new data set.  Change all optimization flags from 1 to 0.  Run this set using CUTOFF=6, GNORM=30, and OPT-H.  That will optimize the positions of all the hydrogen atoms.

7. After the job has run, use the .arc file to make a new data set.  Run this new set with keywords 0SCF and PDBOUT.  Examine the resulting file to see if any hydrogen atoms have migrated to form salt bridges.  If they have, examine the bridge to see if it is chemically sensible.

8. If everything is still okay, edit the data set to change all optimization flags from 0 to 1, and re-run with keywords CUTOFF=6 GNORM=30 T=7d plus a CVB keyword, if necessary.

9. If desired, add all the PDB preamble (everything in the PDB file from "HEADER" to the line before the first atom) to the data set as comments.  Put an asterisk at the start of each comment to indicate that it is a comment.  If desired, add the keyword  START_RES(text).  If the preamble, and START_RES(text) if necessary, is added, then when PDBOUT is used, the resulting file will be almost indistinguishable from a regular PDB file.

10. Once the job finishes, edit the ARC file to make a new data set with keywords CUTOFF=9 GNORM=10 T=7d plus the CVB is necessary, and re-run.

11. Edit the ARC file to make a preconditioned starting MOPAC data set.  This can be used for following a reaction path, finding a transition state, etc.
